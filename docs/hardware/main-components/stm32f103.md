# STM32F103CBT6 — Microcontrôleur interface

Le STM32F103 est le processeur d'interface de la carte STeaMi. Il exécute le firmware DAPLink (comme le micro:bit), gérant les communications USB, la programmation drag-and-drop, le WebUSB et l'accès à la mémoire flash externe.

## Caractéristiques

| Caractéristique | Détail                                                                                   |
| --------------- | ---------------------------------------------------------------------------------------- |
| Modèle          | [STM32F103CBT6](https://www.st.com/en/microcontrollers-microprocessors/stm32f103cb.html) |
| Fabricant       | STMicroelectronics                                                                       |
| Cœur            | ARM Cortex-M3 @ 72 MHz                                                                   |
| Flash           | 128 Ko                                                                                   |
| Firmware        | DAPLink                                                                                  |
| Horloge         | Quartz 8 MHz                                                                             |
| Boîtier         | LQFP48                                                                                   |
| Datasheet       | [PDF](https://www.st.com/resource/en/datasheet/stm32f103cb.pdf)                          |

## Endpoints USB

Le firmware DAPLink fournit quatre endpoints USB :

| Endpoint | Protocole          | Fonction                                        |
| -------- | ------------------ | ----------------------------------------------- |
| HID      | CMSIS-DAP          | Débogage du MCU applicatif                      |
| CDC      | Port série virtuel | Communication série avec le MCU et l'ordinateur |
| MSC      | Stockage de masse  | Flash virtuel — drag-and-drop programming       |
| WebUSB   | Interface web      | Interaction directe depuis un navigateur        |

## Architecture flash interne

| Zone               | Adresse                 | Taille | Description                                        |
| ------------------ | ----------------------- | ------ | -------------------------------------------------- |
| Bootloader         | 0x08000000 — 0x0800BBFF | 47 Ko  | Bootloader DAPLink (jamais touché)                 |
| Config zone        | 0x0800BC00 — 0x0800BFFF | 1 Ko   | Données usine persistantes (révision, calibration) |
| Interface firmware | 0x0800C000 — 0x0801FBFF | 79 Ko  | Firmware DAPLink                                   |
| DAPLink settings   | 0x0801FC00 — 0x0801FFFF | 1 Ko   | Paramètres DAPLink                                 |

## Chaîne de démarrage

[![Chaîne de démarrage de la STeaMi V1c : le bootloader DAPLink du STM32F103 reste en mode MAINTENANCE si le bouton Reset est tenu au branchement, sinon il lance le firmware DAPLink, qui programme le STM32WB55 par SWD puis le relance par T_NRST ; le STM32WB55 démarre en flash sur MicroPython ou sur un croquis Arduino](/img/diagrams/chaine-demarrage.svg)](pathname:///img/diagrams/chaine-demarrage.svg)

À la mise sous tension, chaque microcontrôleur démarre sur son propre rail. Le STM32F103 est alimenté en `+3V3_STLINK` par le régulateur LD3985, quand le câble USB est branché ou quand la broche PB2 du STM32WB55 (`ON/OFF_+3V3_STLINK`) le commande, à travers le MOSFET T4. Le STM32WB55 est alimenté en `+3V3@1200mA`, après l'interrupteur DIO7003 et le convertisseur TPS63000 (voir [Alimentation](./power/)). Le STM32F103 ne retient pas le STM32WB55 en reset : les deux démarrent en parallèle.

1. Le **bootloader DAPLink** (0x08000000) démarre en premier. Il reste actif et présente le lecteur **MAINTENANCE** dans trois cas : la ligne T_NRST est à l'état bas (bouton Reset tenu, lu sur PB0), le fichier `START_BL.ACT` a été créé sur le lecteur **STEAMI**, ou le firmware d'interface est absent. Sinon, il lance le firmware d'interface ([`main_bootloader.c`](https://github.com/steamicc/DAPLink/blob/release_letssteam/source/daplink/bootloader/main_bootloader.c)).
2. Le **firmware DAPLink** (0x0800C000) initialise les LEDs, l'UART, l'esclave I2C 0x3B, le bus SPI et la flash W25Q64 ([`steami32.c`](https://github.com/steamicc/DAPLink/blob/release_letssteam/source/board/steami/steami32.c)), puis connecte l'USB : lecteur **STEAMI**, port série CDC, CMSIS-DAP et WebUSB (voir [Endpoints USB](#endpoints-usb)).
3. Un fichier `.hex` ou `.bin` déposé sur le lecteur **STEAMI**, ou une commande CMSIS-DAP (OpenOCD, pyOCD, page web), écrit la flash du STM32WB55 par SWD, sur les broches `T_SWCLK` (PB13) et `T_SWDIO` (PB14, relue sur PB12). DAPLink envoie ensuite une impulsion sur T_NRST (PB0) : le STM32WB55 redémarre sur son nouveau programme.
4. Le **STM32WB55** démarre en flash, sa broche BOOT0 étant tirée à 0 par R116 (100 kΩ, sur la V1b et la V1c). Il exécute le firmware MicroPython (`boot.py`, `main.py`, puis le REPL sur le port série) ou un croquis Arduino (`setup()`, puis `loop()`).

La mise à jour du DAPLink par le lecteur **MAINTENANCE** est décrite dans [DAPLink](../../software/daplink#mise-à-jour-du-firmware).

:::info Release
La V1b suit la même chaîne que la V1c (feuille FP14 identique). Sur la V1a (indices A et A1), le LD3985 prend le rail POWER sans passer par T4, et la broche PB15 du STM32F103 commande l'entrée `PWR_ENn` du DIO7003. Le bouton Reset (SW1) y est relié à `T_NRST_STLINK`, en sortie du tampon U18 (74LVC1G07) que pilote PB0 : d'après le schéma, le bootloader ne voit donc pas l'appui sur PB0, et le lecteur **MAINTENANCE** s'obtient avec `START_BL.ACT`. Ce point n'a pas été vérifié sur une carte V1a. Enfin, R116 n'est pas montée sur la V1a (voir [Composants non montés](../components/not-fitted)) : BOOT0 (partagé avec LED_BLE) n'a pas de tirage à 0.
:::

## Protocole I2C (adresse 0x3B)

Le STM32F103 est accessible via I2C1 à l'adresse 0x3B, au format 7 bits (0x76 au format 8 bits, constante `I2C_STEAMI_ADDRESS` de [`steami_i2c.h`](https://github.com/steamicc/DAPLink/blob/release_letssteam/source/board/steami/steami_i2c.h)). Les adresses des autres composants du bus sont regroupées dans [Capteurs et bus internes](../pin-mapping/internal-bus#adresses-i2c). Les commandes disponibles :

| Commande     | Code | Description                                     |
| ------------ | ---- | ----------------------------------------------- |
| WHO_AM_I     | 0x01 | Identification du composant                     |
| SET_FILENAME | 0x03 | Définir le nom de fichier pour l'écriture flash |
| GET_FILENAME | 0x04 | Lire le nom de fichier courant                  |
| CLEAR_FLASH  | 0x10 | Effacer la mémoire flash W25Q64                 |
| WRITE_DATA   | 0x11 | Écrire des données dans la flash                |
| READ_SECTOR  | 0x20 | Lire un secteur de la flash                     |
| WRITE_CONFIG | 0x30 | Écrire dans la config zone                      |
| READ_CONFIG  | 0x31 | Lire la config zone                             |
| CLEAR_CONFIG | 0x32 | Effacer la config zone                          |
| STATUS       | 0x80 | Lire l'état de la dernière opération            |
| ERROR        | 0x81 | Lire le code d'erreur                           |

## Connexions

| Signal      | Pin STM32F103               | Description                         |
| ----------- | --------------------------- | ----------------------------------- |
| I2C1_SCL    | PB10 (V1b, V1c) ; PB6 (V1a) | Bus I2C interne (partagé avec WB55) |
| I2C1_SDA    | PB11 (V1b, V1c) ; PB7 (V1a) | Bus I2C interne                     |
| USART1_TX   | PB6 (V1b, V1c)              | Connecteur J9                       |
| USART1_RX   | PB7 (V1b, V1c)              | Connecteur J9                       |
| UART3_TX    | PB10 (V1a)                  | Connecteur J9                       |
| UART3_RX    | PB11 (V1a)                  | Connecteur J9                       |
| LED_STATUS  | PA9                         | LED status verte                    |
| LED_FLASH   | PB1                         | LED communication verte             |
| LED_DAPLINK | PA6                         | LED DAPLink bleue                   |
| SWCLK       | PA14                        | Port SWD (debug)                    |
| SWDIO       | PA13                        | Port SWD (debug)                    |

D'après la feuille FP14 de chaque indice, le bus I2C interne arrive sur PB10/PB11 à partir de l'indice B1 (V1b, V1c) : c'est le périphérique I2C2 du STM32F103, relié à l'I2C1 du STM32WB55 (encadré « I2C2_STM32F103 = I2C1_STM32WB55 » du schéma). Le firmware DAPLink configure ces broches ([`steami_i2c.c`](https://github.com/steamicc/DAPLink/blob/release_letssteam/source/board/steami/steami_i2c.c)). Sur les indices A et A1 (V1a), le bus arrive sur PB6/PB7 (I2C1 du STM32F103), et PB10/PB11 portent UART3_TX/RX vers J9.

## Signaux SPI vers flash W25Q64

Le STM32F103 pilote la [flash W25Q64](./w25q64) par son périphérique SPI1, placé sur PB3, PB4 et PB5 par le registre de réaffectation des broches (AFIO). Le chip select, la protection en écriture et le reset sont des GPIO.

| Signal    | Pin STM32F103 | Broche LQFP48 | Test Point |
| --------- | ------------- | ------------- | ---------- |
| SPI1_SCK  | PB3           | 39            | TP42       |
| SPI1_MISO | PB4           | 40            | TP41       |
| SPI1_MOSI | PB5           | 41            | TP40       |
| FLASH_CS  | PC15          | 4             | TP39       |
| FLASH_WP  | PB8           | 45            | TP38       |
| FLASH_RST | PB9           | 46            | TP37       |

Ce brochage est identique sur les indices A et A1 (V1a), B1 (V1b) et C (V1c), d'après la feuille FP14 de chacun. Il figure aussi dans le firmware DAPLink ([`steami_spi.c`](https://github.com/steamicc/DAPLink/blob/release_letssteam/source/board/steami/steami_spi.c) pour SPI1 et le chip select, [`w25q64.c`](https://github.com/steamicc/DAPLink/blob/release_letssteam/source/board/steami/w25q64.c) pour la protection en écriture et le reset). Le changement « Update I2C1, USART1, RST, SPI1 » du cartouche de l'indice B porte sur l'I2C et l'UART (voir [Connexions](#connexions)), pas sur les broches de SPI1 ni de la flash.
